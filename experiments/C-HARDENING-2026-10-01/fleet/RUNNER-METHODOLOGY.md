# Runner settings and comparison method

The native Intel x86_64, AMD x86_64 and ARM64 runs use the same pinned logical
CPU **2 within each machine**, for every flag, compiler, revision and timed
diagnostic. CPU numbers do not identify equivalent hardware across machines;
all speedup ratios are computed within one machine.

## Pinning and interference

- Each benchmark starts through `taskset -c 2`. The full-driver shell and its
  children inherit that affinity. The hardware-profile target is pinned the
  same way. No timed workloads run concurrently on one machine.
- Intel CPU 2 has SMT sibling CPU 50. The selected AMD and ARM CPUs expose
  only CPU 2 in their thread-sibling masks. The metadata and topology snapshots
  retain the actual mapping; do not assume this mapping on a different host.
- During the audit, a live ARM percentile-driver check independently reported
  `/proc/<pid>/status` → `Cpus_allowed_list: 2`.
- Before timing, sample `/proc/stat` over three seconds. Require every CPU
  below or equal to 20% busy, summed CPU utilization below or equal to 80%
  (0.8 fully busy core), and the selected core's SMT sibling at most 5% busy.
- During timing, exclude CPU 2 from that other-work calculation and sample
  every three seconds. Two consecutive violations terminate **only our own
  process group**, discard that attempt, wait for idle, then retry. The
  controller allows five attempts and a one-hour bound per invocation.
- Fleet coordinators are left running. No instance provisioning, coordinator
  pause, global CPU isolation, governor change or turbo/frequency lock is used.
  Builds finish before timed work starts. Inventory probes run after timing.

Pinning removes core migration; it does not remove frequency variation,
cache effects, ASLR or executable-layout sensitivity. Report repeated-run
spread and observed pair ranges. Do not interpret nested loop iterations as
independent machine-level replications or claim 1% precision automatically.

## Builds and measurement order

Primary source is `d21d0843b492023077553b3eba26b3efa16c15f5`; the earlier
`bcb5c1f` is a supplemental reference. Source/input hashes and emitted compiler
flags are saved. Drivers are byte-identical to their git objects. The caller
stays at O3; only library optimization changes between Os and O3. Core timing
builds have no LTO. Every configuration passes CTest before timing.

Full-driver order per compiler is **Os, O3, O3, Os**. Add another Os/O3 pair
if identical-binary invocation medians/read elapsed times differ by more than
5%. Keep all successful observations, including the original variation.
Write statistics use the median of iterations 11–100. Read statistics use
whole-process wall time because the driver's printed Mqueries/s has only two
decimals; that time includes three warmups, twenty measured passes and setup.
The write referee uses four significant digits; the read referee uses three.

The bounded supplemental probe uses range 1..1e9 with two and three digits,
sequential writes and dense p50/p99/p99.9 queries. Discard its first three of
nine runs per precision. This matches the server's range/precision at two
digits, but is a synthetic distribution, not a Redis/Valkey throughput test.
Both server snapshots use two digits; benchmark clients default to three,
with different ranges from this synthetic read workload.

Consumer size builds hold GCC O3/LTO application objects fixed and vary HDR
flags and final linker GC. They use libc, TLS disabled and systemd disabled.
Measure actual server and benchmark executables, `.text`, GNU size's broader
text column, stripped bytes and exports. These consumers embed a static HDR
archive; this is not an HDR shared-library benchmark. Heap-counter allocation
does not change with these compiler/linker flags.

## Saved inventories

Each machine's `raw/<machine>/results/inventory/` contains:

- `lscpu --json`, logical CPU/core/socket/NUMA topology, and `lsmem --json`.
- Descriptive `hwinfo --cpu --memory --system` fields. Unique identifiers,
  serial numbers and arbitrary raw system inventory are excluded from git.
- GCC/G++/Clang/Clang++, target triple, linker, assembler, libc, CMake, make,
  Python and OS/kernel versions; actual flags are saved alongside the inventory.
- CPU-2 topology, available governor/driver/frequency/boost settings, SMT state,
  CPU isolation, selected non-identifying boot options, ASLR, perf permissions,
  NMI watchdog, transparent huge pages, clock source and memory snapshots.
- Consumer `.make-settings`, when generated by the normal build.

If hwinfo is absent, the collector attempts to download the distribution's
packages and extract them under the owned temporary directory, without
installing packages or changing the host's package database. Availability and
command exit codes are recorded. Identifying raw inventories stay outside the
public repository. Frequency/free-memory readings are post-run snapshots,
not proof those values were held constant during timing.
