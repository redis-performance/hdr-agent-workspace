## Evidence and implementation audit

The measured `6930fd7` candidate improves dense p99 from 4,570 to 1,133 ns/query, with a reported paired throughput interval of +297.36% to +306.47%. The immutable referee reports 0.22 to 0.90 Mqueries/s and a sequential mean write change of -0.076%. These are distinct experiments, not interchangeable uncertainty estimates (`M6-004/RESULT.md:44`, `:62`). The broader matrix exposes early-crossing losses: sig1 index16 is 2.959 to 3.517 ns/query, index31 4.166 to 6.951, index32 4.167 to 7.395, and index47 5.597 to 10.438 (`M6-004/prefix-mask32/matrix/summary.json:50`). The corresponding -16% to -47% values are throughput changes, not latency increases. This matrix overlapped the unresolved sampler and is screening evidence only (`M6-004/RESULT.md:86`).

The current `df89e1f` passes release/sanitizer ctest and 34,680 expanded oracle checks, as does the baseline under the stated validation conditions. It has no timing result (`M6-004/quartet32/VALIDATION.md:14`). The checked source is a 16-counter prefix in quartets, then width-32 unsigned reductions, then a scalar tail; nonzero offsets take the original normalized scalar scan (`src/hdr_histogram.c:711`, `:726`, `:738`, `:755`, `:799`). The default macro remains 4, so reproducing the candidate requires `HDR_M6_SCAN_BLOCK=32` (`:717`); a plain default build does not exercise the intended finalist.

**New assembly observation:** the quartet edit changes the non-crossing loop's machine code despite leaving its source reduction text unchanged. `prefix-mask32/scan.s:94–119` loads all 32 counters into vectors, reduces them, then adds the prior running total once. `quartet32/scan.s:82–110` loads the first four counters into scalar registers and executes four dependent additions starting from the prior running total; the other 28 counters are reduced with vector instructions, and both pieces are combined. Crossing resolution then reuses the first quartet's partial sums and reloads later quartets (`quartet32/scan.s:119–151`). Thus “the width-32 reduction is unchanged” is a source-level statement only. It does not establish preserved long-scan throughput. The recorded function size also grows from 253 to 461 instructions (`quartet32/VALIDATION.md:10`). Neither observation proves a slowdown without measurement.

The portable code already emits vector loads, `add.2d`, and `addp.2d`; lack of NEON intrinsics is not a missing mechanism. M6-005 should stay deferred.

### Assumptions that must stay explicit

- **Monotonic cumulative counts:** skipping a block is correct when bucket counts are nonnegative, their sum matches `total_count`, and the sum fits signed 64 bits. Under these invariants every unsigned reduction and signed cumulative conversion is bounded. Arbitrary negative buckets invalidate block skipping even without arithmetic overflow.
- **Negative recordings are an unresolved API boundary:** `hdr_record_values` and its atomic twin check the value/index but do not reject negative `count` (`src/hdr_histogram.c:534–572`); the header does not explicitly state a nonnegative-count restriction (`include/hdr/hdr_histogram.h:128–156`). Valid removals that leave nonnegative buckets are covered; arbitrary negative states are not. The root reviewer verified the proposed counterexample through the public recording API using `population/semantic_probe.c:10–14`: record (16,+2), (20,-2), (48,+2). All calls are accepted and total_count is 2. Baseline `8c4cdcc` returns p50=16; both `6930fd7` and `df89e1f` return p50=48. The width-32 block over indices16–47 sums to zero and skips the earlier crossing. This is a verified behavioral difference, not merely a speculative overflow concern. Resolve the supported invariant before accepting wider skipping; unsigned casts do not solve this semantic difference. Do not silently add write-path validation in a scan experiment. Live upstream deduplication is unavailable, so this report makes no claim that the issue is new or untracked upstream.
- **Read consistency:** atomic recording documentation explicitly permits inconsistent concurrent observations (`include/hdr/hdr_histogram.h:146`). The tests and performance claims should use quiescent histograms. They do not establish snapshot semantics during concurrent writes.
- **Offsets:** the candidate preserves the normalized scalar fallback (`src/hdr_histogram.c:726`). Existing tests reinterpret a fixed physical array using offsets 0, +1, -1, n-1, and 1-n (`scan_validate.c:29`), which covers useful boundaries. Add an independent physical rotation of a fixed logical histogram as a metamorphic control; merely reproducing the same normalization formula in an oracle can share an error. Decoder handling of malformed offsets belongs to Stage 0, not these source variants.
- **Tails and bounds:** width-32 blocks start at logical index16, then 48, 80, etc. `idx <= n-BLK` ensures complete blocks and `idx<n` handles the remainder. Normal `counts_len` is a multiple of the sub-bucket half-count (`src/hdr_histogram.c:427`), hence a multiple of 16 for precisions 1–5. Many configurations leave a 16-counter scalar tail because of the prefix; “length divisible by 32” does not mean “no tail.” Cover all tail lengths reachable through valid configurations. Do not describe every arbitrary residue as a valid public allocation.
- **Precision and bucket units are separate axes:** existing validation spans significant figures 1–5 but `make_hist` always uses `hdr_init(1, 1000000000, sig, ...)` (`bench.c:32–36`). It does not cover coarser lowest-discernible values or diverse range geometry.
- **Empty semantics:** the scanner returns value 0 when no target is found, then `hdr_value_at_percentile` applies lowest-equivalent rounding only for p==0 and highest-equivalent rounding otherwise (`src/hdr_histogram.c:805`, `:857–867`, `:277–299`). The root reviewer verified `hdr_init(1024, 1000000000, 3, ...)` with `population/semantic_probe.c:30–37`: baseline, measured candidate, and quartet candidate all return singular p0=0 and p50=p100=1023, while their batch API leaves outputs 1,1,1. A literal `return 0` at the public singular entry point would change behavior, and replacing singular calls with batch calls would also change these empty results. All current unit-1 singular empty cases hide the rounding distinction.
- **Metadata shortcuts:** p0/min and p100/max substitutions are unsafe without additional proof. Recording negative counts still calls `update_min_max`, removals need not repair extrema, and expanded checks deliberately construct counts without min/max metadata (`scan_validate.c:49`). Preserve the actual cumulative scan semantics.
- **Target rounding:** the scalar oracle independently scans counters but shares the floating-point target formula and index conversion helpers (`bench.c:38–52`). Its large-count fixture totals about 3.38e15 (`scan_validate.c:64–69`), below 2^53 and far below the known near-INT64_MAX target-cast overflow boundary. It does not establish correctness for all int64 totals. Keep rounding unchanged; test representable target boundaries separately and label pre-existing undefined float-to-int cases rather than attributing them to a scan edit. Do not use fast-math.

## S1 — evaluate `df89e1f` as it stands

**Anchors:** `src/hdr_histogram.c:755–797`; `M6-004/quartet32/scan.s:82–151`; `M6-004/quartet32/VALIDATION.md:3–23`; `NEXT-RUN.md:23–28`; `run_scan_matrix.sh:5–17`.

**Mechanism:** quartet tests reduce the number of scalar per-counter comparisons when a crossing is late in a wide block. Existing correctness checks exercise all early crossing positions 0–255. The new machine code can reuse early partial sums.

**Counterargument and risk:** all 32 counters are still loaded before the first crossing decision. Index16 cannot avoid that wide-block work. The scalar quartet added to every long block and near-doubled instruction footprint could sacrifice long scans or mixed-workload instruction-cache behavior. A fixed p99 single-bucket case trains branch predictions far more consistently than alternating early/late queries.

**Benefit/confidence:** potentially substantial recovery at late crossings 31/32/47; moderate mechanism confidence, low confidence of an across-matrix win. Long-scan preservation is unproved.

**Isolated experiment:** after cleanup, first rerun `6930fd7` versus `8c4cdcc` to verify the screening pattern, then run `df89e1f` versus the same baseline with identical O2 flags and block32. Add a direct `6930fd7` versus `df89e1f` paired comparison for attribution; do not infer their difference by subtracting unrelated runs. Use fresh output directories and retain binary/source hashes. Existing queued commands are in `NEXT-RUN.md`; the runner itself compiles its harness, so it must not be invoked during this review.

**Falsifiers/controls:** apply every shared matrix row below. The intended mechanism is falsified if clean measurements do not recover the crossing losses, if the losses move to another early boundary, or if long-scan gain materially falls. An early-cell regression cannot be hidden by a large long-scan average. If intervals straddle the declared threshold, status is inconclusive. A code-size increase alone does not reject the candidate, and vector instructions alone do not accept it.

## S2 — isolate a compact crossing resolver, only if S1 warrants it

**Anchors:** current inline crossing logic at `src/hdr_histogram.c:763–791`; first-quartet hoisting at `M6-004/quartet32/scan.s:82–110`; later unrolled quartet chains at `:129–240`; prior compact scalar crossing loop at `M6-004/prefix-mask32/scan.s:128–138`.

**Mechanism/proposition:** place quartet crossing resolution in one bounded static helper, reached only after the full block test. For a diagnostic experiment, prevent inlining of that helper with a narrowly scoped compiler guard, leaving prefix, block width, offset fallback, target calculation, and tail unchanged. The objective is to recover an entirely vector block reduction and keep repeated crossing code out of the caller. Inspect the resulting assembly; source extraction alone does not guarantee either result. No public API/ABI change is needed.

**Counterargument and risk:** a call and argument setup occur on every wide-block crossing, including the exact short queries being repaired. Preventing cross-function optimization can discard useful partial sums and trigger reloads or spills. The helper itself may still unroll. This is a tradeoff experiment, not a claim that smaller code is automatically faster; compiler-specific controls need separate portability review.

**Benefit/confidence:** modest-to-large possible benefit only if S1 loses long-scan throughput or mixed-case performance from the observed code shape; low confidence before S1. It may be decisively worse for isolated early crossings.

**Isolated experiment:** branch from the measured S1 revision, change only crossing-resolver placement, and pair against that revision plus `8c4cdcc`. Do not simultaneously expand the prefix, alter width, add an empty check, or change compiler targeting. If assembly does not remove the scalar dependency from the wide-block body or reduce useful caller footprint, stop before interpreting timings as a test of this mechanism.

**Falsifiers/controls:** use every shared matrix row. Require recovered long-loop/mixed-query behavior without newly losing the 16–47 cases or write controls. Add a hot single-histogram comparison against randomized switching between several histograms and other library functions to expose any footprint benefit. Reject if call cost dominates, spills increase without a measured compensating benefit, or only the instruction count improves. If S1 already passes all gates, deprioritize this variant.

## S3 — bypass an empty scan while preserving final rounding

**Anchors:** `src/hdr_histogram.c:848–853` and `:857–867`; empty return at `:805`; equivalent-value conversion at `:277–299`; `bench.c:139–149`; `M6-004/prefix-mask32/read/summary.json:2–32`.

**Mechanism/proposition:** for a supported, quiescent nonnegative histogram with `total_count==0`, set the internal `value_from_idx` to zero and pass through the existing p0/highest-equivalent result conversion. This removes a scan of the entire allocated counts array. It is independent of block-width selection and should first be evaluated alone on `8c4cdcc`.

**Evidence versus expectation:** saved empty cases still cost about 4.6 microseconds on baseline and 1.15 microseconds on prefix-mask32. A constant-work result is therefore a credible empty-query opportunity; no new speedup has been measured or estimated here. Confidence in the complexity reduction is high under the invariant; confidence of a default win is low-to-moderate because ordinary tiny queries take only a few nanoseconds.

**Counterargument and risk:** the extra count check can hurt common nonempty early exits and mixed empty/nonempty branch prediction. `total_count==0` implies empty only under the invariant; a positive/negative cancelling histogram can have existing nonzero percentile results. Do not ship this proposal until the negative-count contract is resolved. Preserve original rounding and original nonempty arithmetic; do not expand to p0/min or p100/max shortcuts.

**Isolated experiment:** one empty-case guard on the baseline, followed by exact comparison of empty results with baseline for unit magnitudes 0, 1, 3, and 9 and all significant figures. Then pair empty-only, nonempty-only, and predetermined mixed populations. Only combine with a winning wide scan after both independent experiments pass, followed by full interaction validation.

**Falsifiers/controls:** all shared matrix rows apply. Explicitly reject a literal-zero implementation on coarser empty histograms. Reject if pure nonempty tiny/crossing queries breach the declared non-regression limit, or if only an unrealistically all-empty aggregate wins. Cover newly initialized, reset, decoded-empty, valid removal-to-zero, and nonzero-offset empties. A mixed distribution must not serve as permission to change arbitrary negative-state behavior.

Acceptance remains the plan's targeted improvement of at least 2% and no more than 1% regression on the other immutable referee path with supporting paired bounds. Early-crossing regressions additionally prevent recommending a universal singular-scan default even when long-scan gains dominate an aggregate. Stop the candidate family after three controlled no-wins or evidence that its mechanism no longer addresses the cost.
