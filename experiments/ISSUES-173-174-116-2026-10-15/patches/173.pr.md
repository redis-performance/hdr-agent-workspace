## What

`hdr_value_at_percentiles` now returns the lowest equivalent value for a slot whose requested percentile is exactly `0.0`, the same as `hdr_value_at_percentile(h, 0.0)`. A small static helper (`percentile_bound`) is used at the three places the batch scan emits a value: the blocked loop, its tail, and the iterator fallback that handles a non-zero `normalizing_index_offset`. `hdr_value_at_percentile` itself is not changed.

## Why

The singular API special-cases p0 and returns `lowest_equivalent_value`, which equals `hdr_min(h)`. The batch API always returned `highest_equivalent_value`, so the same input gave different answers from the two APIs whenever the first populated bucket is wider than 1. Examples:
- `hdr_init(100, 1e7, 3)` with 5000 recorded: batch p0 gave 5055, singular gives 4992.
- With 0 recorded at `lowest_discernible_value = 100`: batch p0 gave 63, singular gives 0.

## Compatibility

This is a behaviour change, and it affects only batch slots whose percentile is exactly `0.0` on a non-empty histogram. Those slots now return the bucket's lower bound (`== hdr_value_at_percentile(h, 0.0) == hdr_min(h)`) instead of its upper bound.

The rule checks the raw input for `== 0.0`, the same as singular C, Java `getValueAtPercentile` and Rust `value_at_quantile`:
- `-0.0` counts as p0.
- Negative percentiles, tiny positives such as `1e-12`, and NaN still return the upper bound.
- Go's `<= 0` rule was deliberately not followed.

Every other slot returns exactly what it did before. The scan cost is unchanged: one double compare per emitted slot, and nothing is added to the per-counter loop. The packed histogram already used this rule for its plural API. Its test comment, which called dense plural p0 a known divergence, is updated.

## Tests

- New `test_value_at_percentiles_p0_equals_singular` uses percentiles `{-1, -0.0, 0, 0, 1e-12, 10, 50, 99.9, 100, 150}` and checks:
  - Batch equals singular for every slot. This runs with lowest 1, lowest 100, and lowest 100 with a recorded 0, each on the blocked path and on a rotated copy (offset 101) that forces the iterator path. The rotated copy is built the same way the existing offset tests build theirs.
  - Absolute assertions: p0 equals `hdr_min(h)`, `-0.0` equals p0, recorded 0 gives p0 of 0, and `-1` / `1e-12` keep the upper bound (greater than p0).
  - The tail loop is reached by temporarily shrinking `counts_len` to a non-multiple of the block size; the original length is restored before close. `hdr_init` never produces such a length, so this is the only way to cover the tail site.
- `test_percentile_singular_equals_plural_with_offset` now includes 0.0, and its comment no longer describes p0 as an excluded divergence.
- The packed `test_percentile_edges` test adds a dense-vs-packed plural p0 parity check on a bucket of width 4 (value 5001).
- Removing the fix from any one of the three emit sites, or changing the rule to `<= 0.0` or `< 1e-9`, makes the dense test fail. The new tests also fail on unpatched upstream.
