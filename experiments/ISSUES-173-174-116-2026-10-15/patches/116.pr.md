## What

Every percentile query now returns 0 when the histogram has no recorded values (`total_count == 0`):

- `hdr_value_at_percentile`: an `HDR_UNLIKELY(h->total_count == 0)` early return at entry. The scan, the AVX2 loop and the offset-aware path are not changed.
- `hdr_value_at_percentiles`: the unresolved-slot fill added by #174 now writes 0 when `total_count == 0`. This is a one-line change and adds nothing to the scan.
- `hdr_packed_value_at_percentile` / `hdr_packed_value_at_percentiles`: the same empty check. The plural zero-fills and returns before it sorts or scans.
- Docs: a new `@return` line on `hdr_value_at_percentile`, and the `hdr_value_at_percentiles` note now says that unresolved slots are 0 on an empty histogram. The packed header's contract paragraph now reads "Empty mean/stddev and percentiles return zero."

## Why

On an empty histogram the scan finds nothing and returns 0. The singular API then rounded that up to `highest_equivalent_value(0)`, so the reported percentile was a value that was never recorded: 63 with `lowest_discernible_value` 100, 511 with 1000. Java (`getValueAtPercentile`: "Returns 0 if no recorded values exist"), Rust (`value_at_quantile`) and Go (`ValueAtPercentile`) all return 0 here.

## Compatibility

- Behaviour change, for empty histograms only. Previously, with `lowest_discernible_value > 1`, any percentile other than 0.0 returned `2^unit_magnitude - 1`, e.g. 63 at lowest 100 and 511 at lowest 1000. It now returns 0. The batch and packed APIs, which followed that value after #174, now also return 0.
- `lowest_discernible_value == 1`: unchanged, because `highest_equivalent_value(0)` was already 0.
- Non-empty histograms: unchanged, including a recorded value of 0. That still reports its bucket's range, e.g. p50 = 63 at lowest 100.
- Dense/packed parity is preserved: dense and packed, singular and plural, are all 0 on empty.
- No ABI or struct change.
